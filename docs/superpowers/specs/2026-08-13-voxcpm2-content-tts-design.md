# voxout —— VoxCPM2 对外内容语音输出设计

- 日期：2026-08-13
- 状态：已批准，待实现
- 依据：[75.01 本地 TTS 模型选型](../../../../../../Life%20OS/70-79%20Resources%20%26%20Tools/75%20Technical%20Refs/75.01%20本地%20TTS%20模型选型.md)（选型结论）+ 本次会话在 M4 Pro 上的六轮实测（见 §3）

## 1. 目标与范围

把 Life OS `60-69 Content Production` 里的 markdown 内容渲染成可对外发布的 48kHz 音频，音色固定且可验证。

**本轮范围**

- 短帖路径端到端跑通：`63 Short-form Posts/*.md` → 单个 48kHz wav + manifest
- 音色锚点机制（这是正确性要求，不是可选项，理由见 §4）
- 两道自动闸门：内容完整性、音色一致性

**明确不在本轮**

- 真人声音克隆（无参考录音；机制建好，锚点先用合成音占位，见 §7）
- 长文 continuation 链（第二层，见 §8）
- 常驻服务、流式输出、多说话人

## 2. 语言选择：Python

不是生态偏好，是这台机器上的硬约束。

1. **唯一的快路径本身是 Python 对象图。** VoxCPM2 在 Apple Silicon 上最快的实现是 MLX，入口是 `mlx_audio.tts.utils.load()` 返回的 `nn.Module`，生成是 Python generator。Rust 无 MLX 绑定，candle 无 VoxCPM2 实现。
2. **选型文档的数据已否掉非 Python 路径。** 唯一无需 Python 的选择是 llama.cpp-omni GGUF，同为 M4 Pro / Metal / Q8_0，官方 RTF ~1.76，而 MLX 路径实测 0.91–0.96。用 Rust 绑 llama.cpp 等于主动选一个慢近一倍的后端。
3. **Amdahl 定律使语言选择失去意义。** RTF ~0.93 意味着 1050 字要 191 秒计算。编排层的全部工作——markdown 清洗、切句、WAV 拼接、写 manifest——是毫秒级。编排层即使无限快，端到端提速 < 0.1%。
4. **Rust 当外壳会主动制造两个新问题。** 调 CLI 则每次重付 1.2–2.0s 模型加载；走 HTTP 则 Python 照样在跑，只是多了一个进程和一层 IPC，且拿不到 `prompt_audio` / `inference_timesteps` 这类进程内参数。

Rust 会赢的场景（均不成立）：分发二进制给无 Python 环境的机器；高并发硬实时流式服务。

## 3. 证据基线

全部为本次会话在 MacBook Pro M4 Pro / 48GB / macOS 26.5.2 / mlx-audio 0.4.8 / MLX 0.32.0 / VoxCPM2-8bit 上实测。探测脚本见 §11。

| 实测项 | 结果 |
|---|---|
| 模型加载 | 1.22–1.95s，**按进程付** |
| RTF（带锚点，350–1050 字）| **0.91–0.96**，快于实时 |
| 采样率 | 48000 Hz |
| 固定种子 → 输出 | **逐样本 bit 相同**（max abs diff 0.00e+00）|
| 无截断长度 | **≥1050 字**（s/汉字 漂移 1.3%，ASR 覆盖率 98.4–98.9%）|

### 三条对选型文档的修正

1. **RTF 不是 1.12，是 0.91–0.96 —— 快于实时。** 文档结论表把「RTF 1.12 慢于实时」列为代价，但那是 56/173 字短样本的**含开销**值。文档自己算出的边际 RTF 是 1.083，而长文本带锚点实测到 0.93，说明连边际值都被高估。渲染 3.4 分钟音频耗时 3.2 分钟。
2. **发现一个文档未覆盖的严重缺陷：zero-shot 模式跨调用不保音色。** 详见 §4。文档每个模型只跑单次生成，测的是 RTF / 内存 / 可懂度，从未测跨调用音色一致性——而这恰是「对外内容输出」的载重属性。
3. **VoxCPM2 的单次长度上限远高于文档验证的 173 字。** 实测 1050 字仍零截断，意味着 `63 Short-form Posts` 现有最长篇（953 字）单次调用即可，短帖路径无需切段。

   > **实现阶段推翻了这一条。** 「零截断」测的是截断，不是跳读。模型会读完开头、跳掉中间整句、正常收尾，音频波形上看不出异常，而当时闸门 1 还不存在，没有仪器能看见。补测：单次调用 213 / 540 汉字的 ASR 覆盖率是 55.40% / 85.00%，80 汉字是 68.75%，78 汉字 97.44%，≤65 汉字只剩同音字级偏差。切段阈值因此从 900 汉字改为 **60**，且改为**段落原子**——段落之间一律分开，与阈值无关。详见 §5 与 T13a。

### 四条对本设计的修正（实现阶段实测）

1. **库的 `real_time_factor` 与本文档的 RTF 互为倒数。** mlx-audio 的 `GenerationResult.real_time_factor` 是 `音频时长/耗时`，本文档 §3 用的是 `耗时/音频时长`。照抄库的字段会让「0.93」这个数在两处含义相反，而两者都在 1 附近，反转后依然像个合理读数——这种错误不会自己暴露。实现只记原始的 `generation_seconds` 与 `audio_seconds`，派生留给消费方（`synth.py` 模块文档）。顺带两条同类：`audio_duration` 是 `"HH:MM:SS.mmm"` 字符串不是数字；`patch_size` / `decode_chunk_size` 一律从模型实例读而不用常量，取错会直接导致静默截断。

2. **截断上限是可算的，不需要试。** 生成循环最多跑 `max_tokens` 个 patch，每 patch 产出 `patch_size × decode_chunk_size / sample_rate` 秒音频；VoxCPM2 是 4 × 1920 / 48000 = 0.16 秒。默认 `max_tokens=2000` → 320 秒 → 按 0.2127 秒/汉字约 1500 汉字。于是预算改为**事前**按汉字数推算（`budget.plan_max_tokens`），超上限直接报错并给出「能装下多少汉字」，而不是把上限悄悄放大。§11 的「真实上限未知」由此关闭。

3. **参考音在模型内部被降到 16 kHz。** 后果是 LTAS 比较必须截在 8 kHz（Nyquist），否则锚点与 48 kHz 输出在高频段比的是重采样补出来的零，余弦相似度会虚高。`config.LTAS_MAX_HZ = 8000.0`，并有一条测试钉住它不超过 Nyquist。`anchor.wav` 仍要求 48 kHz——它同时是我们自己的度量对象，与输出必须同率才可比。

4. **闸门 1 必须**两侧都做数字归一化**，「只保留汉字」做不到中和数字形式。** §6 原先写的机制是错的：去掉非汉字并不能中和「第一百二十二天」与「第122天」的差异，而是把数字整个删掉，得到「第一百二十二天」对「第天」，实测覆盖率 0.2857——一次完美的渲染被判成丢了 71% 的内容。正确做法是先用 `cn2an` 把两侧的阿拉伯数字都改写成中文数字，**再**取汉字比较。另加繁转简：Whisper 会输出繁体（「發」對「发」），不折叠会被记成缺失（T13b）。

## 4. 核心发现：音色锚点是正确性要求

### 测量方法

用两个互相独立的判别量，避免单一指标失真：

- **p10 F0（浊音基频 10 分位，即音高底）** —— 说话人身份指标。一个人的基频下界近似生理常数，语调只往上走。
- **LTAS 余弦（长时平均频谱）** —— 音色指纹。

关键在于先建标尺再读数：

- **正控制**：单次连续生成后切成三段。音色**按构造相同**（同一次采样轨迹）。其读数即「同一人跨内容」的抖动地板。
- **负控制**：已知不同说话人的两段（142 Hz vs 222 Hz）。即「同一人」的天花板。

### 结果

| 方案 | p10 F0 极差 | LTAS 余弦下界 | 标尺位置 |
|---|---|---|---|
| 正控制（同一人）| **0.9%** | 0.965 | 地板 |
| **`ref_audio` 锚点** | **3.4%** | 0.922 | **87.7%** |
| continuation 链 | 5.2% | 0.919 | 86.8% |
| `instruct` 造音色 | 14.7% | 0.804 | 53.9% |
| 无锚点（朴素切段）| 53.9% | 0.616 | 天花板（坏）|
| 仅固定随机种子 | **67.5%** | 0.849 | 比坏基线更坏 |

**结论**：朴素 zero-shot 切段会让一篇文章的各段变成不同的说话人（142 / 222 / 220 Hz）。固定随机种子无效——它只保证「同输入 → bit 级同输出」，换文本音色照样跑。**唯一有效手段是 `ref_audio` 锚点**，把 p10 F0 极差压到 3.4%，接近同一人 0.9% 的地板。

因此音色锚点在架构里是强制的，不是可选配置。

### 一个方法论陷阱（务必保留在文档里）

第一版用**中位数 F0** 当身份指标，得出「锚点方案 20.8%，FAIL」的结论。这是错的：正控制显示同一人读三句不同话，中位数 F0 天然有 5.1% 极差——中位数被**语调**污染了。换成 p10 后锚点方案落到 3.4%。

这条对闸门设计有直接后果：**闸门 2 必须用 p10，不能用中位数。** 用中位数会被正常语调起伏不断触发假警报，而一个总在误报的闸门两周内就会被关掉——等于没有闸门。

## 5. 架构

库内核 + 瘦 CLI。不起服务、不设守护进程。模型加载 1.2–2.0s 摊进一次渲染的百秒级生成，占比 < 1%；常驻进程是纯运维成本换一个测不出收益的优化。

```
markdown ──[prepare]──> 可朗读文本
                            │
                    [chunk（段落原子；>60 字的段落才切）]
                            │
      音色档案 ──────> [synth：一个已加载模型，逐段生成]
      anchor.wav                  │
      anchor.txt             音频段序列
                            │
                       [verify] ──> 两道闸门
                            │
                     [assemble] ──> 48kHz wav + manifest
```

本轮切段时，各段是**独立调用、共用同一锚点**，段间不做 continuation 条件化（continuation 属第二层，见 §8）。这一点已由 E 探测支持：同锚点独立切段的 p10 F0 极差是 3.4%，音色不会散。

### 模块

| 模块 | 职责 | 依赖 |
|---|---|---|
| `profile.py` | 音色档案：铸造 / 加载 / 校验锚点 | scipy, mlx_audio |
| `markdown.py` | md → 可朗读文本 | 无 |
| `normalize.py` | 阿拉伯数字 → 中文数字；Latin 单位缩写展开 | cn2an |
| `textmatch.py` | `han_only` / `coverage`（纯文本，从 verify 拆出以便脱离 mlx_audio 单测）| stdlib difflib |
| `chunker.py` | 段落原子化；**单个段落** >60 字才在句末切开 | 无 |
| `synth.py` | 持有**一个**已加载模型，逐段生成 | mlx_audio |
| `metrics.py` | F0 / LTAS 原语（本次探测脚本升格）| numpy, scipy |
| `verify.py` | 两道闸门 | mlx_audio (whisper), metrics |
| `assemble.py` | 拼接 + 写 wav + manifest | scipy, numpy |
| `cli.py` | 命令行 | 以上全部 |

每个模块 90–150 行量级，单一职责，可独立测试。

### 音色档案格式

存放于 `Life OS/60-69 Content Production/68 Writing Assets/voice/<name>/`：

```
anchor.wav     48kHz 单声道参考音
anchor.txt     其精确转录（VoxCPM2 的 ref_text，保真度最高的模式需要它）
profile.toml   来源、铸造参数（seed / instruct）、基线 p10 F0、创建日期
```

`profile.toml` 记录基线 p10 F0，闸门 2 用它做参照，而不是只看段间极差——这样单段渲染也能被检查。

因为固定种子 → bit 级相同（§3），合成锚点可由 `(seed, text)` 二元组复现；`profile.toml` 记下这两项，wav 丢失可一字节不差地重铸。

## 6. 两道闸门

两道都由**实测的失败**推导，不是想象的风险。

### 闸门 1：内容完整性（ASR 覆盖率 ≥ 97%）

动机：选型文档实测 Kokoro 在 173 字输入下于第 115 字硬切断，**丢弃 27% 内容且不报错**。对外内容管线最不能承受的失败模式。

方法：Whisper-large-v3-turbo 回环转录，与原文比汉字覆盖率。

实现要点（踩过的坑）：

- **必须用 `difflib.SequenceMatcher` 的匹配块，不能手写贪心逐字匹配。** 手写贪心版在中文数字与阿拉伯数字形式不一致处永久失步：写「四万八千赫兹」，模型正确读出，Whisper 转回「48000赫兹」，贪心匹配从此错位，对**完整无损**的音频报出 3.5% 覆盖率。换 difflib 后同一段音频报 98.5%。
- 比较前**两侧都过一次数字归一化，再取汉字**（`一`–`鿿`），并折叠繁简。只取汉字并不能中和数字形式，它把数字整个删掉——见 §3 修正 4。
- 阈值 97%：实测三个长度稳定在 98.4–98.9%，留约 1.5 个百分点余量。

  > **实测重读后阈值不动，但余量比这里写的小。** 上面这三个读数用的是 numeral-free 语料，且当时比较口径还没有双侧归一化与繁转简。T13 按闸门实际的量法（整篇一次转写）在两篇真实短帖上各生成两次：213 汉字 99.06% / 99.06%，540 汉字 98.89% / 97.96%。真实余量按最差那次算是 **0.96** 个百分点，不是 1.5——同一篇帖子换一次生成就差了 0.93 个百分点。仍守 0.97 的理由是两侧之间有一段空白：真丢内容的读数在 55–85%，噪声侧聚在 98–99%。下调的触发条件写在 `config.COVERAGE_MIN`：某次读数低于 97% **且**音频经人工听审确认完整。

失败行为：**渲染失败，不产出音频**，写差异报告（原文 / 听到 / 缺失区段）。`--force` 为逃生口。

### 闸门 2：音色一致性（p10 F0 相对锚点漂移 ≤ 15%，取各段中位数）

方法：对每个输出段算 p10 F0，与 `profile.toml` 记录的锚点基线比；多段时另算段间极差。

阈值 6% 的依据：同一人地板 0.9%，锚点方案实测 3.4%，坏基线 53.9%。6% 留出一倍余量，且距坏区有一个数量级。

> **这一节的判据与阈值都在实现阶段被推翻（T13c）。** 6% 在两篇真实短帖上误报率 100%，根因有三层，只改阈值只能治第三层：
>
> 1. **判据本身有定义缺陷。** 原实现取各段漂移的**最大值**。极值统计量的期望随抽样数上升，于是同一个音色、同一个基线，6 段的帖子读出 10.65%，14 段读出 13.79%——「文章更长」被读成「音色更飘」。改为取各段漂移**绝对值的中位数**：同两篇各生成两次，四个读数是 5.35 / 5.02 / 4.72 / 5.04%，极差 0.6 个百分点且与段数无关。
> 2. **基线是单次读数。** 文本与说话人固定、只换采样，p10 F0 的极差实测 7.71% 与 14.91%，而基线是此后每一次判定的分母。改为取 `BASELINE_SAMPLES=3` 次**锚点条件下**生成的中位数，各份读数与极差写进铸造日志。
> 3. **阈值低于自己估计器的噪声底。** 上面那三个标尺数（0.9 / 3.4 / 53.9%）都是在**文本固定**的条件下测的，而闸门要判的是文本各不相同的真实内容——同条件重测，地板本身就有 7.33% 的段间极差。新阈值 15%：真实内容最差中位数 5.35% + 基线自身可能偏的约 3% ≈ 8.4%，之上留 1.8 倍，距坏区仍有 3.3 倍。
>
> 标尺已改为可重跑：`tests/fixtures/probe_voice_controls.py` 在一次运行里现生成三个条件（地板 = 锚点+一次生成切段，工况 = 锚点+N 次生成，天花板 = 零样本换人）。首轮 p10 极差 7.33% → 11.39% → 40.85%，LTAS 余弦 0.919 → 0.870 → 0.586，锚点补掉 87.9% 的缺口（§4 用另一套统计量记的是 87.7%）。
>
> 同时记下一个**本节原先没有预料到的失效**：对天花板那一列，「相对基线的漂移」根本不可用。零样本每次抽一个随机说话人，它离我们的基线多远纯属抽签——实测抽到 160.2 / 106.4 / 128.7 Hz，其中 160.2 几乎正中 165.81 的基线，中位漂移只读出 22.41%，低于同一批音频自己的段间极差 40.85%。若三段都抽到基线附近，「换了个人」在 p10 上会完全隐形，而 LTAS 余弦照旧是 0.586。这正是本节坚持用两个独立判别器的价值，也说明**闸门 2 只判 p10 是已知弱点**，LTAS 升为判据列入待办。

失败行为：告警并在 manifest 中标记，附具体数字。不硬失败——音色漂移是可听审的质量问题，不是内容丢失。

### 闸门 1 的结构性盲区：数字读法

**ASR 覆盖率无法检测数字读错。** 若模型把「122」读成「一二二」而非「一百二十二」，Whisper 转录回来同样是「122」，覆盖率 100%，闸门全绿而音频是错的。这不是阈值问题，是该指标对这类错误**完全盲**。

而这类错误在真实语料里是常态而非边缘情况：`63 Short-form Posts` 现有两篇短帖每篇都含多处阿拉伯数字（「第 122 天」「7 月 24 号」「4 月」）。

尝试过用时长做代理检测（音节数不同：「一百二十二」5 音节 vs「一二二」3 音节），**结论是不可用**——短句的句级韵律方差（±0.3–0.5s）与待测信号（0.16–0.64s）同量级，测不出来。

**采用的方案是消除风险而非检测风险**：合成前用 `normalize.py` 把阿拉伯数字确定性地改写成中文数字，文本里不留可misread 的目标。选用 `cn2an`（0.5.24）而非自写，实测覆盖全部真实用例，含百分号（`72.2%` → `百分之七十二点二`）与日期（`7月24号` → `七月二十四号`）。`cn2an` 不处理 Latin 单位缩写（`GB`、`kHz`），由一个项目自有的小字典补上。

归一化后文本变纯中文，而 Whisper 仍会把听到的中文数字写回阿拉伯数字，因此闸门 1 的 difflib 稳健性仍然必需（见上）。

### 交叉校验（不依赖 ASR）

manifest 记录 **秒/汉字**（用 `speech_seconds`，不含我们自己插进去的段间静音）。同一音色不可能随文本变长而读得更快，所以该值下降即内容丢失。实测三个长度为 0.2142 / 0.2114 / 0.2127（漂移 1.3%）。这条与闸门 1 完全独立——本次会话两次因主指标失真而误判，都是靠独立旁证救回来的，故写入常规输出而非仅调试用。

> **实现阶段这条旁证真的抓到了一次失效**，值得记下它的读数。段落原子化之后的四次渲染（两篇 × 两次生成）：
>
> | 渲染 | 汉字 | 秒/汉字 |
> |---|---|---|
> | cal1 / verify-07-22 | 213 | 0.2299 / 0.2321 |
> | cal2 / verify-07-31 | 540 | 0.2320 / 0.2341 |
>
> 四个读数的极差 **1.83%**，而其中跨了 2.5 倍的文本长度；干净那两次之间（213 对 540 汉字）只差 **0.84%**。远在计划要求的 15% 之内，说明这个量对文本长度基本不敏感——正是它能当独立旁证的前提。
>
> 同一篇 213 汉字的帖子在**单次调用**（T13a 的跳读态）下读 0.1698 与 0.1661，比正常带最低值短 **26.1%**。两条独立仪器同时报警：覆盖率 55.40%，秒/汉字 −26%。旁证不是理论上的保险，它在真实失效上响过。
>
> 顺带解释一处偏差：上面 §6 原记的 0.2114–0.2142 比新的正常带低 6.8–8.0%。那三个读数取自 350 / 700 / 1050 汉字的**单次调用**，而单次长调用现已知会跳读——方向与跳读一致，但幅度远小于 26%，故只记「方向吻合」，不归因。`config.SECONDS_PER_HAN_ESTIMATE = 0.30` 作为 token 预算的保守上界不受影响（它只需高估）。

## 7. 克隆升级路径

本轮锚点是一段冻结的合成音。取得真人录音后：

```
68 Writing Assets/voice/house/anchor.wav   ← 换成真实录音
68 Writing Assets/voice/house/anchor.txt   ← 换成对应转录
profile.toml                               ← 更新 source 与基线 p10 F0
```

**代码零改动。** 因为音色一致性本身必须走 `ref_audio`（§4），克隆机制本轮不得不建——克隆不是加出来的功能，是一致性的副产品。

后续录制真声时需要的配套（不在本轮）：朗读稿设计、录音质量校验、Whisper 预转录 + 人工校对生成精确 `ref_text`。

## 8. 长文（第二层）

短帖路径过闸门后再做，在同一 synth loop 上加 continuation：`prompt_audio` = 上段音频，`ref_audio` = 锚点（库的 Mode 5：combined reference + continuation）。

定位：**音质优化项，不是正确性要求。** 因为 E 探测已证明同锚点独立切段能保住 3.4% 一致性，continuation 解决的是段间韵律衔接，不是音色漂移。

开启前必须实测过闸门，不预设结论——单测 continuation 是 5.2%，略差于纯锚点的 3.4%，组合效果未知。

## 9. 错误处理

| 情形 | 行为 |
|---|---|
| 音色档案缺失 / 不完整 | 明确报错 + 给出铸造命令 |
| `anchor.wav` 采样率非 48kHz | 拒绝加载，提示重采样 |
| 权重未缓存且离线 | 明确报错，附 `HF_ENDPOINT` / `HF_HUB_DISABLE_XET` 配方 |
| 闸门 1 不过 | 渲染失败，写差异报告，不出音频 |
| 闸门 2 不过 | 告警 + manifest 标记，仍出音频 |
| 输入 markdown 为空 / 清洗后无可读内容 | 明确报错，不产出静音文件 |

所有渲染默认设 `HF_HUB_OFFLINE=1`（权重已缓存 3.0GB）。理由：选型文档 §4 记录本机网络会导致「静默挂死」，实测挂 29 分钟零进展。宁可离线时明确失败，不要静默挂死。

## 10. 测试策略

目标覆盖率 80%+。TDD：先写测试。

**单元（不碰模型，快）**

- `metrics`：用已知频率的正弦波测 F0 估计器——有闭式真值可对，符合「参照值要么是闭式解，要么是另一条独立算路」
- `coverage()`：构造已知缺失区段的文本对，断言覆盖率；**必须含一个数字形式不一致的用例**，锁死 §6 那个贪心失步 bug 的回归
- `markdown`：frontmatter / 标题 / 链接 / 代码块清洗，纯函数
- `chunker`：边界条件——刚好 60 字的段落（`>` 而非 `>=`）、无标点长句、单句超限、段落原子化（拼回去汉字数守恒）

**集成（碰模型，慢）**

- 短文本全链路，断言两道闸门通过、输出 48kHz、manifest 字段完整
- 锚点复现性：同 `(seed, text)` 两次铸造，断言 bit 相同（锁死 §3 的性质）

**回归装置**

本次三个探测脚本进 `tests/fixtures/`，它们已是有效的回归装置：正控制/负控制标尺尤其应保留——阈值一旦要调，得先重跑标尺。

> 实现阶段改为**重写而非搬移**。原脚本各自带一份 F0 与极差实现（与 `metrics.py` 重复），且 `probe_control.py` 的负控制读的是 `/tmp` 下上一次探测留下的 wav——那些文件早已不在，脚本其实跑不动了。搬过来会得到一个看着能跑、实际跑不动的回归装置。现存两个：
>
> - `tests/fixtures/probe_voice_controls.py`：三个条件在一次运行里现生成，度量从 `voxout.metrics` 导入。
> - `tests/fixtures/probe_chunk_fidelity.py`：切段保真度。

## 11. 未覆盖 / 待验证

- **无主观听感评价。** 本设计的两道闸门只管内容完整与音色一致，管不了好不好听。锚点选定需人工听审。
- **阿拉伯数字读法本身仍未验证**，但已通过前置归一化绕开（见 §6）。仍需人工听审确认：单位字典的覆盖是否够、归一化后的读法是否自然。
- **F0 估计器的有效范围是 60–400 Hz**（人声基频范围）。超出会发生八度错误：实测 440 Hz 正弦被判为 220.2 Hz。这是设计取值的后果而非缺陷，但必须作为断言写进测试，避免日后被当成 bug「修」掉。
- ~~**截断上限只测到 1050 字**，真实上限未知。>900 字启用切段是保守策略。~~ **已关闭**（§3 修正 2）：上限是 `max_tokens × patch_size × decode_chunk_size / sample_rate` 算出来的，`budget.plan_max_tokens` 在生成前就据此拒绝。真正的限制不是截断而是**跳读**，那条另立于下。
- **单次调用的跳读上限是软的，只测到汉字粒度。** ≤65 汉字干净、78 汉字 97.44%、80 汉字 68.75%。阈值取 60 留了一档，但 65–78 之间没有细测，且未测这个上限是否随语料（句长、标点密度）变化。
- **闸门 2 只判 p10 F0，对「抽到近基线的另一个说话人」是盲的。** 实测撞到过：零样本抽到 160.2 Hz，几乎正中 165.81 的基线，p10 漂移读 22.41% 而同批音频 LTAS 余弦是 0.586（§6）。LTAS 已实现（`metrics.ltas` / `cosine`）但未接入闸门，升为判据列入 `docs/listening-review.md`。
- **闸门 2 也不再拦单段级的音色事故**（判据改中位数的代价，§6）。离群段以 `segment_p10s` 与 `spread_pct` 呈现给人，靠听审发现。
- **英文与中英混排未测。**
- Whisper 在一段音频尾部出现过疑似幻觉（转出「父亲下车周甚内容到前 bore」）。未确认是合成尾部噪声还是 Whisper 在静音上的已知幻觉。闸门 1 用覆盖率而非字错率，对尾部幻觉不敏感，但需留意。
- **未测 continuation 与锚点的组合效果**（§8）。
